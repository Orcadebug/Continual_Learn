# Laya Continual Learning — Research Log

## Verified architecture (from repo source, main branch, read 2026-10-09)
- `DecisionModel.forward` (laya/common.py): encoder (ModernBERT-large) → `h + type_emb(qtype)` (3 question types only) → 2 shared TransformerEncoder decision layers → `torch.gather` at option-marker positions → ONE shared scorer (LayerNorm→Linear→GELU→Linear→1) → option logits. A separate `act_head` consumes pooled h[:,0] + confidence features (top1, margin, entropy, k/255) → act_logits.
- Training (laya/train.py): `_forward` returns only option logits to the loss — **act_logits are computed but never trained** (confirmed, line: `logits, _act = model(...)`).
- `save_checkpoint` persists weights (fp16), encoder config, tokenizer, config JSON — **no optimizer state, no experience history, no learning-controller state** (confirmed).
- The trainer natively supports `TrainConfig.freeze_encoder` (freezes encoder params, sets encoder.eval(), detaches encoder output in the training forward) and separate encoder/head learning rates. Loss options: `rlcd` (default) and `soft-ce`.
- Checkpoints are separate (English / multilingual / typed-decisions behind a Router): learning in one does not transfer to the others.

## Architectural assumptions under attack (ranked)
1. All lasting knowledge must live in shared weights (encoder + shared head + shared scorer) — every new rule risks moving every old rule.
2. Inference is stateless: no persistent memory or learning state is carried between calls; "learning" = a separate offline training job that emits a new checkpoint.
3. One shared decision pathway for all tasks — task identity exists only as 3 type embeddings (choice/score/noul).
4. Fixed capacity/topology forever; nothing renews or reallocates capacity (plasticity is assumed, not maintained).
5. The act/abstain policy is outside the learning loop (act head untrained by the fine-tuning loss).

## Experiment 1 — Where does forgetting live: encoder or head? (exp1_interference.py)
Design: sequential fine-tuning on 6 synthetic 4-way routing tasks (256 train / 128 test each, templated texts, domain-specific label sets). Two arms, identical data/order/seed/budget (soft-ce, 3 epochs/task, effective batch 16):
- FULL: all parameters trainable.
- FROZEN: encoder frozen (native freeze_encoder), only head-side parameters train.
After each stage: accuracy on all 6 test sets (retention matrix) + a plasticity probe — a deepcopy gets a fixed 1-epoch budget on a never-seen 7th task; its probe accuracy measures remaining learning capacity at that stage.

Registered predictions (before the run):
- P1 (encoder is the interference site): FROZEN forgetting ≈ 0 and much lower than FULL; FROZEN learns each new task nearly as fast.
- P2 (head/scorer is the interference site): FROZEN forgets about as much as FULL — freezing the encoder does not protect old tasks.
- P3 (neither binds at this scale): both arms retain well → interference is not the first wall; escalate task count / rule complexity, and plasticity over long horizons becomes the prime suspect.
- P4 (plasticity): FULL's probe accuracy declines across stages faster than FROZEN's (encoder plasticity loss); equal decline in both arms points at head-level plasticity loss.

## Experiment 1 — RESULTS (T4, 2026-10-09, raw: laya_exp1_results.json)
- Base checkpoint already scored 0.73–0.88 on the synthetic tasks zero-shot (criteria descriptions carry the semantics), probe base 0.88.
- FULL: every task → 1.00, **zero forgetting**, and training one task IMPROVED the untrained ones (e.g., task 3: 0.77 → 0.99 after task 1 only). Plasticity probe 1.00 at every stage.
- FROZEN: essentially **no learning at all**. Trained-task accuracy ≈ base accuracy at every stage (task 1: 0.867 before and after); probe training gained exactly 0.000 at every stage. Only ±0.01 noise on untrained tasks.
- Verdict: P1/P2 NOT convicted — no forgetting occurred in FULL to localize; the tasks shared one underlying skill (match text to criteria semantics), so sequential training behaved like multi-task training (positive transfer). The surprise finding is bigger: **learning in Laya is encoder-bound.** With the encoder frozen, the shipped head (2 layers + scorer, lr 1e-4, 48 updates/task) acquired ~nothing. A "stable encoder + plastic head" architecture — the obvious modular fix — does not work on this evidence: the decision-relevant knowledge lives in the encoder's representations.
- Caveats: tasks too easy/aligned (ceiling effects; probe saturated); head-only arm may be under-budgeted; 6 tasks is short for plasticity decay. → Experiment 2 removes the semantic shortcut.

## Experiment 2 — Arbitrary mappings + rule change (exp2_arbitrary.py)
6 tasks, each 8 invented code words mapped by fiat to 4 generic labels (criteria uninformative; zero-shot should be ≈0.25 chance). 320 train / 128 test per task, 4 epochs/task. Same FULL/FROZEN arms + plasticity probe (7th arbitrary task). Final stage: task 1's mapping is permuted (policy change) and relearned; measure new-rule accuracy, stale-rule accuracy (still answering by the old mapping), and collateral damage to tasks 2–6.
Registered predictions:
- FULL learns each arbitrary task well above chance; retention of earlier mappings now decays measurably (interference appears once knowledge can't ride on shared semantics).
- FROZEN either (a) learns the current task but forgets prior ones → interference lives in the head after all, or (b) stays near chance → encoder-bound learning confirmed decisively.
- Rule change: FULL adopts the new rule fast; stale-rule accuracy reveals whether old knowledge actively resists replacement. FROZEN, if it learned anything, should resist updating the most.

## Experiment 2 — RESULTS (T4, 2026-10-09, raw: laya_exp2_results.json)
- Design worked: base accuracy ≈ chance (0.18–0.35). FULL learns every arbitrary task to 1.00 immediately.
- **Catastrophic forgetting confirmed** for FULL: final accuracies [0.50, 0.66, 0.95, 0.90, 1.00, 1.00]; forgetting [0.50, 0.34, 0.05, 0.10, 0, 0] — a clean recency gradient. Mid-sequence, training even pushed an *untrained* task to 0.04 (below chance): updates actively rewrite unrelated mappings. Task 1's trajectory is non-monotonic (1.0 → 0.96 → 0.53 → 0.44 → 0.62 → 0.50) — a visible stability-gap pattern.
- **Plasticity did NOT decay** in FULL at this horizon: probe-after-fixed-budget [0.43 at base → 0.93, 0.74, 0.97, 0.95, 1.00, 0.95, 1.00]. The base model is initially *slow* to learn an arbitrary mapping (0.43), then becomes fast after learning one — the encoder adapts to the task family (meta-learning confound noted; probe is same-family).
- **Rule change:** FULL adopts the new rule perfectly (new-rule 1.00, **stale-rule 0.00** — zero resistance to replacement) BUT the single-task update damages everything else: tasks 2–6 fall from [0.66, 0.95, 0.90, 1.00, 1.00] to [0.47, 0.48, 0.63, 0.77, 0.98]. Laya has no selective updating: every update is a global overwrite, paid for by all stored knowledge.
- FROZEN: learns nothing again (diag ≈ chance; new-rule adoption 0.29 ≈ chance). Encoder-bound learning confirmed on arbitrary tasks too.
- Net diagnosis after Exp 1+2: adaptation is solved by full FT; **retention under global updates is the binding constraint**; plasticity loss is not (at 6–7 tasks). Sai's local-reorganization hypothesis now has a confirmed disease to cure.

## Experiment 3 — Local reorganization (Sai's hypothesis, first form: locality by depth)
Same Exp 2 protocol/data (seed 777). Arms: FULL (re-run for same-session comparability) vs LOCAL — bottom encoder layers frozen, only the top 10 encoder layers + head-side parameters trainable (native trainer, requires_grad masking; ~1/3 of the encoder plastic, 2/3 stable).
Registered predictions:
- LOCAL learns each task slower than FULL (diag possibly < 1.00 at equal budget) but forgets clearly less (mean forgetting < FULL's 0.165).
- Rule change in LOCAL: new rule adopted with materially less collateral damage to tasks 2–6 than FULL's.
- If LOCAL ≈ FULL on forgetting, depth-locality is not the mechanism → next form: input-gated pockets (adapters/MoE) or associative memory at the scorer (Hypothesis: writable memory).

## Sai's question (2026-10-09 18:22 EDT, verbatim)
"When Laya forgets a task, the information that represented that task has been destroyed. But what if the information is still present, and only the mechanism for reading it has changed?"

This is the storage-vs-retrieval distinction applied to Laya: forgetting could be (a) representational destruction in the encoder, (b) readout drift — the encoder still carries the task's geometry but the shared head/scorer no longer reads it correctly, or (c) co-adaptation drift — the information lives in the encoder↔head pairing, not in either part alone.
Existing hint from Exp 2: task 1 accuracy went 1.00 → 0.53 → 0.44 → 0.62 → 0.50 during later training with NO task-1 data. Pure destruction shouldn't partially heal itself under unrelated training; drifting alignment can.
Probe-confound guard: a strong supervised probe trained on task-1 labels could re-learn the mapping from mere word identity in ANY encoder state, so a big probe proves nothing. The decisive test uses NO new training:

## Experiment 4 — The transplant test (exp4_transplant.py)
Train the FULL Exp 2 sequence; snapshot full weights after task 1 (state S1) and after task 6 (state S6). Build hybrids by swapping the head-side parameters (type_emb + decision head + scorer) between S1 and S6 while keeping the other state's encoder. Evaluate all four combinations on task 1's test set:
- E1H1 ≈ 1.00 (reference), E6H6 ≈ 0.50 (the forgetting, reference).
- E6H1 high → the final ENCODER still carries task 1; the readout drifted. Forgetting = retrieval failure.
- E1H6 high → the final HEAD still reads task-1 representations fine; the encoder destroyed it. Forgetting = storage failure.
- Both hybrids low → co-adaptation: the information lives in the pairing.
Corroboration (training-free, low capacity): label-centroid geometry on post-head marker vectors at S1 vs S6 vs base — do same-label items still cluster at S6?

## Experiment 4 — RESULTS (T4, 2026-10-09, raw: laya_exp4_results.json) — the transplant test
- E1H1 (task-1 encoder + task-1 reader): 1.00. E6H6 (final everything): 0.50 — the forgotten state, reproduced.
- **E6H1 (final encoder + task-1-era reader): 0.50 — NO recovery.** The original reader cannot extract task 1 from the final encoder.
- **E1H6 (task-1 encoder + final reader): 1.00 — perfect.** The final reader reads pristine task-1 representations flawlessly; the reader barely drifted in any harmful way.
- Centroid geometry (weak training-free readout): base 0.19 → S1 0.53 → S6 0.34. A faint geometric residue of task 1 survives in the final encoder, but nothing the model's own machinery can use.
- **Verdict: Sai's retrieval-failure hypothesis is refuted for this setting.** Forgetting here is storage-side: later training overwrites the encoder representations that carried the task, while the shared reader stays compatible across the whole sequence (E1H6 = 1.00 is remarkable — the S6 head reads S1 representations perfectly). Combined with Exp 1/2 (learning also lives in the encoder), one substrate explains both phenomena: **the encoder is simultaneously Laya's learning organ and its forgetting organ.** That is precisely why locality must be imposed inside the encoder (Sai's local-reorganization hypothesis), and why reader-side fixes (versioned heads, readout libraries) cannot rescue forgotten tasks on their own.

## Experiment 3 — RESULTS, corrected run (T4, 2026-10-09, raw: laya_exp3_results.json)
FULL reproduced Exp 2 exactly (same seed → identical numbers; pipeline validated).
LOCAL (bottom 18 encoder layers frozen = 272.2M params; top 10 layers = 122.6M + head trainable):
- Learning crippled: accuracy right after learning each task = [0.32, 0.63, 0.38, 0.47, 0.43, 0.45] vs FULL's 1.00 across the board. It never acquires any arbitrary mapping properly.
- "Forgetting" mean 0.052 is meaningless — there was little learning to forget; several tasks *improved* slightly during later training (slow accumulation of a general code-word skill in the top layers).
- Plasticity probe flat at 0.23–0.35 (vs FULL 0.93–1.00). Rule change adopted only to 0.34 (FULL: 1.00).
- **Verdict: locality by depth is dead.** LRs were matched with FULL; the only difference is which layers may move. Acquiring a new decision rule requires reorganization distributed through the encoder's depth — the discriminative structure for novel tokens is built early and mid-network, not near the output. Sai's locality hypothesis survives only in other forms: locality by subspace within every layer (low-rank deltas), or locality by input (gated pockets that fire per-input), not locality by layer band.

## Experiment 5 — Replay + retirement (the fast-memory/controller test)
Exp 4 reframed the problem: the reader is stable and general; the encoder's stored mappings get overwritten by later global updates. Re-anchoring is therefore the direct countermeasure, and Sai's original three-part sketch (fast memory + slow model + learning controller) becomes testable in its simplest form: FULL fine-tuning where each stage's training mixes in a small replay sample from all previous tasks (fast memory), and at the rule-change stage the superseded task-1 data is RETIRED from replay (the controller's one real decision) while tasks 2–6 continue to be replayed.
Protocol: identical to Exp 2 (seed 777); stage training set = current task (320) + 96 replay items sampled from previous tasks; 3 epochs over the mix (≈78 updates, matched to FULL's 80). Rule-change stage: new task-1 data (320) + 96 replay items from tasks 2–6 only.
Registered predictions:
- Retention: mean forgetting ≤ 0.05 (FULL: 0.165); final accuracies ≥ 0.90 mean.
- Rule change with retirement: new-rule acc ≥ 0.95, stale-rule ≈ 0, tasks 2–6 collateral ≤ 0.05 — i.e., replay protects without resisting legitimate replacement.
- If replay fails, encoder overwrite beats re-anchoring at this scale and expansion architectures (per-era modules + routing without task IDs) become the necessary direction.

## Experiment 5 — RESULTS (T4, 2026-10-09, raw: laya_exp5_results.json)
Every registered prediction confirmed, at the ceiling:
- Learns each task to 1.00 (same as FULL). **Final retention: [1.00 × 6] — forgetting 0.0000 on every task** (FULL: mean 0.165, task 1 −0.50).
- Rule change with retirement: **new-rule 1.00, stale-rule 0.00, tasks 2–6 stay [1.00 × 5] — zero collateral damage** (FULL: tasks 2–6 fell to [0.47, 0.48, 0.63, 0.77, 0.98]).
- Plasticity stays high throughout (probe 0.76–1.00; 0.79 after the rule change vs FULL's 1.00 there — a minor dip, not chased).
- Nuance: unlearned tasks were still pushed around mid-sequence (task 6 hit 0.00 before its turn). Replay does not prevent representational drift; it continuously REPAIRS it for everything stored in memory. Memory membership is what protection means.
- Cost: +~30% updates per stage (96 replay items mixed in) and a stored example memory — cheap against a 421M model.

## SYNTHESIS — what actually limits Laya's continual learning (2026-10-09)
Established by Experiments 1–5 on the shipped English checkpoint:
1. **Knowledge lives in the encoder, distributed across its depth.** The decision head/scorer is a comparatively stable, general reader — after 6 tasks of drift it still reads pristine task-1 representations at 100% (Exp 4). Reader-side fixes alone cannot rescue forgotten tasks.
2. **The failure of naive continual fine-tuning is global representational overwrite** (storage-side, Exp 4): each new task's global update rewrites the encoder regions carrying old mappings — earliest knowledge worst (recency gradient, Exp 2), and even a single rule change taxes all other tasks.
3. **Adaptation is not a problem.** Full FT learns arbitrary new rules to 100% immediately and replaces superseded rules with zero stale residue. Plasticity loss (Dohare) did NOT appear at 6–7 tasks — probe learning stayed fast; whether it appears at 50–500 tasks is untested.
4. **Restricting plasticity fails both ways:** frozen encoder → no learning (Exp 1, 2); top-layers-only → crippled learning (Exp 3). Acquiring new decision rules requires reorganization distributed through the encoder. (Sai's local-reorganization hypothesis: dead in depth form; its subspace/gated forms are now unnecessary as a first resort given #5, and remain untested optimizations.)
5. **What works: full plasticity + a small verified replay memory + retirement of superseded data** (Exp 5) — perfect retention, perfect adaptation, zero collateral at modest cost. Mechanistically: replay re-anchors the encoder representations that global updates keep overwriting; retirement keeps the memory from resisting legitimate change. This validates the brief's three-part architecture (stream → fast memory → slow model, with a learning controller) in its simplest form — and identifies the controller's real jobs: curate what enters memory (verified only), select what gets rehearsed, retire what has been superseded.
6. Still open: horizons of 50+ tasks (plasticity + memory selection under accumulation); task-free gradual drift; semantic-task streams (Exp 1 suggests positive transfer dominates there, so real-world forgetting pressure is likely below this worst case); the act/abstain head is never trained by the fine-tuning loss (code-verified) — an abstention policy cannot currently be learned at all.

## Experiment 6 — The Autonomous Mastery Test, v1 (exp6_autonomous.py)
Sai's proposal (2026-10-09 19:10 EDT): stop handing Laya labeled answers; drop it into an unfamiliar environment with ONE objective and test whether it can generate its own learning experiences — explore, take actions, observe consequences, correct itself, retain discoveries across a single continuous lifetime, adapt to hidden rule changes. The untested assumption from Exp 1–5: Laya can learn from SELF-generated experience (RL), not only from supplied targets.
V1 scope (deliberate reductions, stated to Sai): a custom TEXT gridworld instead of MiniGrid (MiniGrid observations aren't text; Laya eats text — the observe/act/reward interface is identical in structure); 6×6 worlds; 4 move actions; mastery bars scaled to "does the loop work and does memory matter," with the proposal's ≥95%/≥90% bars kept as the program-level targets.
Design: policy = Laya's option scorer over a fixed choice question (the 4 actions); a small value head on the pooled state trains alongside (actor-critic, REINFORCE-style with learned baseline + entropy bonus); rewards +1 goal, −0.01/step, −0.05 wall bump, 50-step cap. One lifetime per arm: P1 empty rooms (100 eps) → P2 key + locked door (120) → P3 HIDDEN RULE CHANGE: door needs a floor switch, the key is now a decoy (100) → P4 empty rooms return (60, retention). Greedy held-out eval (12 fresh layouts) every 25 episodes.
Arms: FROZEN (no learning), RL (online actor-critic only), RL+REPLAY (online + 3 replayed trajectories/episode from a 150-episode FIFO memory — Exp 5's winner, now over trajectories; FIFO = natural retirement of old-era experience).
Registered predictions:
- FROZEN success ≈ 0–15% (base Laya has no reason to navigate well).
- RL learns P1 substantially (eval success ≥ 60% by end of P1) but adapts slower to P3 and enters P4 with degraded P1 skill.
- RL+REPLAY ≥ RL on P2/P3 adaptation speed and clearly better P4 retention (first P4 eval close to end-of-P1 level).
- If BOTH RL arms fail to beat FROZEN materially, the assumption dies at v1: Laya's architecture/objective cannot bootstrap from sparse reward at this scale, and the bottleneck (credit assignment? exploration? representation?) becomes the next investigation.

## Sai's operative success criterion for Exp 6+ (2026-10-09 19:47 EDT)
Not peak performance. In his framing: whether Laya can **become good at something, stay good at it, encounter a change it wasn't warned about, adapt, and then remain competent at BOTH the new and the still-valid old situations.** Judge every arm on: (a) end-of-phase competence, (b) stability across evals (no collapses), (c) adaptation speed after the hidden change, (d) retention when old situations return, (e) simultaneous competence across eras — not on ever touching 1.00 once.

## Experiment 6B — Policy Extraction Test (proposed by Sai 2026-10-09 20:13 EDT)
Sai's challenge to the "knowledge in the distribution" reading: sampling > greedy may NOT mean learned knowledge that argmax fails to extract; it may mean the environment rewards exploration/stochasticity while Laya is evaluated as a deterministic MEMORYLESS decision-maker. Third bottleneck named: Learning + Remembering + **Using learned behavior reliably**. Also his stats check: 0.75 on 12 eval episodes = 9 successes; 0.58 vs 0.75 is two episodes — v2 eval noise is large.
VERIFIED in Laya's own README (read 2026-10-09): published checkpoints use the SEQUENTIAL option layout with a documented position effect (issue #131) — on 62 banking intents, **16.3% of answers changed with presentation order**; rotation averaging via `option_order` cut that to 6.1%; sequential checkpoint gives the same answer when shuffled only 91.7% of the time (~8% of decisions flip on reorder alone). A parallel, order-invariant layout exists but **no published checkpoint uses it**.
Replay-loss inspection (Sai asked before blaming the buffer): my Exp 6 replay is NOT imitation — it re-runs the on-policy REINFORCE loss (current-policy logp × (stored Monte-Carlo return − current V), + value loss) on trajectories generated by OLDER policies, with **no importance-sampling correction**. Operative risks: distribution mismatch (his hypothesis 2), plus a poison he didn't name: every action inside a FAILED episode gets negative advantage — including its many correct moves — and replay applies that push 3× (1 online + 2 replays).
BLOCKER (Padfoot's design gap): v2 saved no checkpoints and ran as a subprocess — the RL arm's weights no longer exist. 6B therefore runs as Exp 6C: a production run replicating v2's RL arm through P1+P2 (same seeds/hyperparams) that SAVES its policy, then the extraction test on that frozen policy.
6B design (Sai's, implemented faithfully): identical weights, zero learning, identical world seed sets (40 episodes × empty + keydoor per strategy). Strategies: (1) greedy argmax, (2) sample T=1.0, (3) sample T=0.5, (4) sample T=2.0, (5) greedy + option-order rotation averaging (4 rotations, probabilities averaged per action), (6) greedy + last-4-moves history appended to the state text. Diagnostics: success, avg steps, mean action entropy, mean top-2 margin, repeated-cell visit rate, two-step oscillations per episode.
Padfoot's registered predictions: sample T=1 ≥ greedy; rotation-averaged greedy beats plain greedy with fewer oscillations IF positional bias is a real contributor (~8% order-flips × ~45 steps ≈ 3–4 corrupted decisions/episode — enough to break routes); history cuts oscillations specifically; if all six cluster ≈0.40, extraction is exonerated and the learned distribution itself is the bottleneck.

Verdicts against Sai's interpretation table:
- "Sampling beats greedy" → CONFIRMED decisively (0.075 vs 0.33–0.45, paired seeds, both worlds). The stall mechanism is the cause: deterministic + memoryless + blocked move = identical next state = same action forever.
- "Rotation averaging rescues greedy" → REFUTED here. Laya's positional bias is real (README) but not binding: with margins ≈ 0.005 there is almost no signal to corrupt — averaging noise yields averaged noise (margin after averaging: 0.004).
- "History rescues greedy" → REFUTED as an extraction fix on this policy: history moved margins (0.009 → 0.044) yet produced literally identical trajectories; the policy was never trained to read history, so the text is inert decoration at the stall states. (Whether a history-TRAINED policy navigates better remains open — now a training-side question.)
- "All policies remain weak" → ALSO TRUE: best strategy = 0.45 vs 0.367 random.
**Exp 6 line synthesis:** two of Sai's three bottlenecks bind in sequence. ## Experiment 9 — Curated self-imitation (exp9 cell)
Three targeted mechanisms against Exp 8's two named failures (echo chamber + stale anchor), all self-relative (no external labels):
1. **Efficiency admission:** an episode enters memory only if its length ≤ max(14, 1.6 × the running median successful length in that phase) — wandering successes stop teaching wandering.

## Sai's reframing + Experiment 16 design (2026-10-10 10:04 EDT — his analysis, adopted)
Sai's updated diagnosis: "Laya can learn from its own successful experiences. What it cannot yet do reliably is turn those experiences into reusable, stable skills. That's a different problem from catastrophic forgetting." The attacked assumption: a successful trajectory mixes causal, unnecessary, and counterproductive-but-unpunished actions, and unconditional imitation reinforces all three; plus the policy's state distribution shifts away from its demonstrations after every update (the imitation-learning distribution-shift problem). The remaining research problem, his formulation: **Experience → Reusable knowledge → Reliable behavior.** Autonomous discovery is demonstrated (limited setting); reliable general-purpose skill acquisition is not.

**Exp 15 verdict criteria (Sai's, registered before Exp 15 results):** judge ONLY on held-out end-to-end battery across independent lifetimes vs the Exp 14 distribution. If it merely raises confidence/entropy metrics while the battery stays near Exp 14, optimization strength was not the bottleneck.

**Experiment 16 — controlled comparison (Sai's design):** same behavior rules, matched seeds, matched update budget per episode across arms; the only difference is what a successful episode contributes as training data:
- Arm A: full successful trajectories (current self-imitation baseline).
- Arm B: post-milestone suffix only (tests whether cleaner demonstrations improve downstream decisions; registered risk, Sai's: it may teach finishing while deleting the examples that teach beginning).
- Arm C: milestone-conditioned segments — pre-milestone and post-milestone segments stored as separate examples (reach-the-mechanic segment ends at milestone; finish segment starts there). **The deeper bet if 15 and 16 fail (Sai's, registered as the Exp 17 candidate):** a second learning pathway — a WORLD learner alongside the decision learner. Success-only imitation discards most evidence (a blocked move still teaches the world's structure). ## Experiment 17 — CANDIDATE DESIGN, DRAFT (registered 2026-10-10 while Exp 16 runs; finalize after Exp 16's verdict)

Sai's bet (2026-10-10): if Exp 15 and Exp 16 fail, stop tuning self-imitation and build a world-model pathway — a second learner predicting P(o_{t+1}, r_t | h_t, a_t) trained on ALL interactions (failures included; every step is a correctly-labeled example, dense signal, labels never wrong), with action selection by comparing predicted consequences against the objective.

Draft realization on this stack (to be finalized once Exp 16's decomposed metrics show where behavior breaks):
- Predictor: keep the Laya encoder. Input = current ego observation text + candidate action (action appended as a text line, e.g. "Action: north."). Target = the decision-relevant feature set of the next state, all directly readable from the true world after the step: agent displacement (dx, dy in {-1,0,1}^2, 9-way), milestone flag after step (has_key / switch_on), door_open after step, goal_reached (bool), reward (3-way: goal / step / bump). Multi-head classification on the pooled encoding — a supervised problem with dense, never-wrong labels (the Exp 7 lesson: supervised gradients on these states sharpen fine; it was the RL/imitation signal that was weak).
- Training: online, on EVERY behavior step of the lifetime (not just successes), same optimizer discipline as the current recipe (encoder lr 1e-5, head lr 1e-3). No memory curation problem: transitions do not go stale the way policies do — the world's dynamics are stationary within a phase, and the rule change (P3) is exactly what the predictor must re-learn from fresh prediction errors.
- Action selection (replaces imitation argmax): one-step lookahead. For each of the 4 actions, predict next-state features; score = predicted goal_reached (large) + milestone gain + goal-distance reduction - step cost, with fixed weights registered before the run; the imitation policy (still trained as in Exp 16 arm A) serves only as tie-breaker. Behavior keeps the same 30% novelty exploration for coverage. Multi-step rollout is deferred: it requires rendering predicted features back into observation text (feasible — ego_text is a deterministic function of these features — but it is a second layer to add only if one-step lookahead shows signal).
- Protocol: identical lifetime shape (P1 80 / P2 100 / P3 100 / P4 40), identical greedy eval + battery + decomposed milestone metrics; 2 lifetimes; verdict on the battery against the Exp 14 / 15 / 16-A distributions, per Sai's criterion.
- Registered expectations (draft): prediction accuracy on held-out transitions should exceed 90% within the first phase (the dynamics are simple and fully observed in features); if the predictor is accurate but planned behavior still fails the battery, the bottleneck is the scoring/objective side, not learning — a cleaner localization than self-imitation ever gave. Primary risk: the feature set omits something the text carries (mitigation: features are derived from the same world state that generates the text, so the set is Markov by construction).
- Status: DRAFT. Do not build until Exp 16's verdict lands; if Exp 16's arms separate cleanly on the battery, this design is revised or shelved accordingly.

## Experiment 16 — CONSISTENCY AUDIT (2026-10-11, under Sai's Laya R&D Directive §4)

## Experiment 17 — REGISTRATION (2026-10-11, under Sai's Laya R&D Directive §§5/9; supersedes the 2026-10-10 draft design and EXP17_DESIGN_SCAFFOLD.md, whose battery >= 0.60 prediction is NOT adopted — it predates the Exp 16 audit and has no evidential basis)

INSTRUMENTATION SPEC (applies to all Exp 17 evals and all future experiments):
- Episode-level eval logging: every eval/battery episode writes one record {arm, rep, world, episode_seed, door_required, agent_start, goal_pos, milestone_reached, success, steps, success_via_milestone} to a JSONL results file.
- door_required := (agent_x < 4) != (goal_x < 4) in keydoor/switch worlds (wall at x=4; key and switch always spawn on the agent's side per World.reset_layout, goal on any free cell). Milestone metrics are reported (a) overall, (b) conditioned on door_required episodes only, (c) with the no-milestone success decomposition always shown.

- Raw counts (x/N) accompany every rate. Model checkpoints (state_dict) saved per lifetime in-runtime and their save reported; durable artifacts remain scripts + JSON (runtime storage is ephemeral — recorded as a known limitation, not hidden).

SCIENTIFIC QUESTION: Does action-conditioned transition prediction extract useful, behaviorally relevant knowledge from ALL interactions (failures included) — and does acting on those predictions beat the existing self-imitation policy? Two stages; Stage 2 runs only if Stage 1 shows genuine action-conditioning.

CURRENT EVIDENCE: Exps 15+16 — neither optimization density nor trajectory structure reliably beats full-trajectory self-imitation (battery ~0.44); the Exp 16 audit showed the battery is dominated by door-optional layouts. Supervised gradients sharpen Laya to 95%+ on decision tasks (Exp 7) while self-imitation on successes only — a sparse, success-filtered signal — plateaus. Every environment step, success or failure, carries a correctly labeled transition; that signal is currently discarded except on successful episodes.

COMPETING EXPLANATIONS for the plateau: (i) signal sparsity/filtering — successes-only imitation lacks the data density and the negative examples (world-model hypothesis); (ii) representation — the encoder cannot express dynamics-relevant distinctions (tested by the frozen-encoder diagnostic); (iii) action-selection/planning — knowledge exists but 1-step consequence scoring cannot exploit it (Stage 2 discriminates); (iv) optimization instability in the online loop (Exp 12/13 pattern).

STAGE 1 — PREDICTION (does action conditioning carry real information?)
- Data: ONE fixed transition dataset, identical for all arms. Collection policy = sampling from the shipped Laya scorer + 30% novelty steps (Exp 6B: untrained scorer ~ uniform; effectively a coverage policy), 400 episodes per world (empty/keydoor/switch), episode seeds 910000+i; held-out = i % 4 == 3 (layout-level split, disjoint seeds). Every step records: obs text (ego format, Exp 12+ fixed text), action, and true next features from the World: displacement (dx,dy) 9-class, has_key_after, switch_on_after, door_open_after, goal_reached, reward_class (goal/step/bump), done.
- Arms: A persistence (rule: nothing changes; reward=step; done=False). B action-blind learned predictor (input = obs text only). C action-conditioned (input = obs text + "Action taken: <a>."). D history-conditioned (C's input + previous action and its result category). C-shuffled control (C trained with action labels permuted, fixed seed) — must collapse to B on displacement. C-frozen diagnostic (C with encoder frozen) — representation localizer.
- Predictor: pooled encoder output h[:,0] (forward_full pathway) -> MLP trunk 1024->256 GELU -> per-target linear heads. Loss = sum of per-target cross-entropies, no class weighting (the persistence trap is exposed by event recall metrics, by design). Encoder trainable at lr 1e-5, heads/trunk lr 1e-3, AdamW, 3 epochs, batch 64. Same budget for B/C/D/shuffled/frozen.
- Primary metrics (held-out episodes): displacement accuracy (primary); event recall+precision for blocked, key_gain, switch_gain, door_open_gain, goal_reached; per-target accuracy table for all arms; calibration ECE (10-bin) for goal_reached and blocked probabilities; action-conditioning benefit = C - B displacement accuracy.
- Predictions registered: (P1) C displacement accuracy >= B + 0.15 and >= A + 0.25 (dynamics here are near-deterministic; a working action-conditioned model should be strong). (P2) C-shuffled displacement within 0.02 of B. (P3) C event recall for blocked >= 0.80; for key_gain/switch_gain >= 0.50 (rare events, pooled counts reported). (P4) C-frozen within 0.05 of C on displacement if the shipped representation already carries dynamics info; a large gap localizes the bottleneck to representation learning, not the prediction objective.
- Falsifiers: C - B < 0.05 on displacement -> action conditioning provides no usable signal in this architecture/input format; Stage 2 does not run; next step is a representation/input-format diagnostic, not planning. C high accuracy but event recall near 0 -> the model learned persistence-like shortcuts; same consequence.
- Cost: collection is inference-only (~45k transitions); each learned arm is a small head-training run. Cheap by design (Directive §16: reject broken implementations before expensive batteries).

STAGE 2 — BEHAVIOR (do predictions improve decisions?) — runs only if Stage 1 P1+P2 hold.
- Lifetimes (2) = Exp 16 arm-A recipe verbatim (phases, admission, core, rounds=5, encoder lr 1e-5, novelty 30%, unified eval) with ONE change: action selection. Planner score(a) = 2.0*P(goal_reached) + 1.0*P(milestone_gain) + 0.3*clip(goal-distance reduction from predicted displacement, -1, 1) - 0.1*P(blocked) - 0.01; actions within 0.05 of the best score are tie-broken by the imitation policy's argmax. Greedy eval = pure planner (same instrumentation as arm A: battery n=24 seed0=707000 + episode-level logging + consistency assert). Weights fixed now; no tuning between lifetimes.

- Predictions: (P5) planner battery overall >= A mean + 0.05 in at least one lifetime and >= A mean in both; door-required-conditioned keydoor/switch success improves more than the overall number (the planner's edge should concentrate where consequences matter). (P6) planner greedy_steps on empty < arm-A's (~44) — consequence scoring should cut wandering.
